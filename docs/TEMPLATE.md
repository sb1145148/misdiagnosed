# 条目模板

复制下面这段，填完再提交。**「判断信号」和「代价」两栏不许留空。**

---

## N. 一句话说清这个坑

**现象**

你看到的是什么。要用「别人也能对上号」的描述，不要写「有点慢」这种。

```
错误示例：请求很慢。
正确示例：同一个 URL，curl 0.4 秒返回，Python 每个请求 30–40 秒，不报错。
```

**判断信号**

一条（最好是一条命令）确认是不是这个坑。**这一栏是整篇的核心。**

```bash
# 可以直接复制执行的命令
```

判定标准要写清楚：看到什么就是，看到什么就不是。

**根因**

实际发生了什么。分点写，最好能落到机制层面（不是「某个版本有 bug」）。

**解法**

按改动成本从低到高排。系统级修复优先于逐脚本打补丁。

**代价**

排查花了多久、丢了什么、影响了什么。**这一栏别人很少写，但它决定要不要防。**

**适用边界**

什么情况下这条不成立 / 会误伤 / 有副作用。
