# misdiagnosed

> **一些会伪装成别的问题的坑。**
> 每条都带「判断信号」——让你在五分钟内确认自己是不是踩了它，而不是查三个小时。

---

## 这是什么

不是教程，不是最佳实践，是**失败记录**。

这里每条都来自真实踩坑，格式固定六栏：

| 栏 | 回答什么 |
| --- | --- |
| **现象** | 你看到的是什么 |
| **判断信号** | 怎么确认是这个坑（通常是一条命令） |
| **根因** | 实际发生了什么 |
| **解法** | 怎么修 |
| **代价** | 排查花了多久、丢了什么 |
| **适用边界** | 什么情况下这条不成立 |

**「判断信号」是全部价值所在。** 没有它，这条记录只对作者自己有用。

---

## 为什么写这个

大多数仓库只放成功路径。但真正浪费时间的，是那些**看起来像 A、其实是 B** 的问题：

```
请求很慢      →  以为是接口挂了      实际是 IPv6 黑洞
磁盘很大      →  以为是附件多        实际是硬链接被摊平
天数是第 13 天 →  以为是记录详细      实际是把采集轮次当自然日
播放只有 7     →  以为是内容不行      实际是同质内容被折叠
```

这四条的共同点：**它们都会让你往错误的方向查**。

## 脚本

```bash
scripts/net-probe.sh          # 判断「慢」是不是地址族问题
scripts/dup-scan.sh DIR       # 找同内容多拷贝（并给出可省的体积）
scripts/timezone-check.sh     # 检查容器时区与报告时区是否一致
```

三个脚本都只读，不改任何东西。

## 收录标准

**收：**
- 有「判断信号」，别人能照着一条命令确认
- 有明确的根因，不是「重启就好了」
- 会伪装成别的问题

**不收：**
- 一次性配置问题（改个环境变量就没了）
- 文档里已经写清楚的东西
- 只有成功路径、没有排查过程的
